# Documentation map

## Start here

- [Architecture](ARCHITECTURE.md): data flow, tensor contracts, model, controller, and deployment
  boundaries.
- [Project status](PROJECT_STATUS.md): what is implemented, evaluated, pending, and safe to claim.
- [Reproducibility](REPRODUCIBILITY.md): environment, artifacts, commands, and evidence rules.
- [Requirements](REQUIREMENTS.md): functional and research requirements with verification status.
- [Datasets](DATASETS.md): acquisition, licensing, intended use, and split policy.
- [Verification](VERIFICATION.md): measured software and engineering checks.

## Research record

- [Final results](FINAL_RESULTS_SUMMARY.md): consolidated development results and all retained or
  rejected candidates.
- [Research protocol](RESEARCH_PROTOCOL.md): hypotheses, split controls, model selection, and event
  evaluation rules.
- [External confirmation protocol](MULTIFOLD_EXTERNAL_CONFIRMATION_PROTOCOL.md): locked-data and
  five-seed confirmation rules.
- [Claims audit](CLAIMS_AUDIT.md): distinction between supplied context and reproducible evidence.
- [Event threshold frontier](EVENT_THRESHOLD_FRONTIER.md): sensitivity versus false-alert policy.

The remaining hypothesis documents are frozen experiment records. They preserve the decision rule,
implementation change, result, and rejection rationale for each controlled candidate. They are
kept because negative results are part of the project's evidence, not because every candidate is
recommended for deployment.
