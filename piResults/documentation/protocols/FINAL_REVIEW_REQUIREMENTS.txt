A. CRITICAL TASK 1 — RECHECK SENSOR IDENTITY
===================================================

WHY THIS IS NEEDED
------------------
The physical breakout/module is confirmed by the author as labeled MPU6050.

However, the archived register dump returned:

WHO_AM_I = 0x70

The paper cannot ignore a disagreement between:
- physical module marking, and
- register-level device identity.

The objective is NOT to relabel the sensor without evidence.
The objective is to create a clean, repeatable identity record.


A1. THREE-BOOT IDENTITY TEST
----------------------------

Perform three completely separate Pi + sensor power cycles.

For each boot:

1. power the Pi and IMU off completely,
2. wait at least 10 seconds,
3. power on,
4. confirm the device I2C address,
5. read WHO_AM_I 100 times,
6. save every returned value,
7. read configuration registers,
8. save i2cdetect output.

Registers to capture:

0x19  SMPLRT_DIV
0x1A  CONFIG / DLPF_CFG
0x1B  GYRO_CONFIG / FS_SEL
0x1C  ACCEL_CONFIG / AFS_SEL
0x23  FIFO_EN
0x37  INT_PIN_CFG
0x38  INT_ENABLE
0x3A  INT_STATUS
0x6A  USER_CTRL
0x6B  PWR_MGMT_1
0x6C  PWR_MGMT_2
0x72  FIFO_COUNT_H
0x73  FIFO_COUNT_L
0x75  WHO_AM_I

Also save:
- I2C device address,
- I2C bus number,
- configured I2C baud,
- OS/kernel,
- script hash.

Required output:
identity_boot1.txt
identity_boot2.txt
identity_boot3.txt
identity_summary.csv

Summary fields:
- boot number,
- unique WHO_AM_I values observed,
- count per value,
- I2C address,
- register values,
- decoded accel range,
- decoded gyro range,
- decoded DLPF setting,
- sample-rate-divider setting,

- DATA_RDY state.

STOP CONDITION:
If WHO_AM_I is identical across all 300 reads, record that result exactly.
Do not "correct" it manually.

B. CRITICAL TASK 2 — CORRECT AND REVALIDATE FIFO
===================================================

WHY THIS IS NOW CRITICAL
------------------------
The previous FIFO A-B-A experiment showed physically implausible full-scale motion while the helmet was stationary.

Polling A1/A2 looked stationary.
FIFO B showed multi-axis rail behavior.

Before the FIFO experiment can be used scientifically, the FIFO implementation must be audited.

The most important checks are:
- FIFO packet byte order,
- FIFO_EN contents,
- accel/gyro order,
- signed int16 conversion,
- endianness,
- sensitivity scale factors,
- packet length,
- FIFO count handling,
- overflow handling,
- decimation rule,
- sample timestamp assignment.
