HELMX — FINAL RASPBERRY PI ACQUISITION A–B–A TEST
=================================================

Purpose
-------
This is the final targeted Raspberry Pi experiment recommended before stopping Pi-side testing for the current HelmX IEEE Sensors Journal paper.

The reason for this test is that the previously tested FIFO/decimated acquisition path produced reconstruction-only confirmed triggers that were not seen in the deployed polling path.

This experiment is designed to determine whether changing only the acquisition method systematically changes the reconstruction-error distribution.

After this experiment, no further Raspberry Pi testing is recommended unless a real journal reviewer specifically requests something new.


IMPORTANT HARDWARE NOTE
-----------------------
The physical sensor module is confirmed by the author as an MPU6050 based on the sensor/module marking.

Do not alter the physical sensor mounting between runs.


EXPERIMENT DESIGN
-----------------
Run three consecutive matched conditions in this exact order:

A1 — DEPLOYED POLLING BASELINE
B  — FIFO / DECIMATED ACQUISITION
A2 — DEPLOYED POLLING REPEAT

Recommended duration:
- 20 minutes per condition

Total experiment time:
- approximately 60 minutes, excluding setup/transitions.

The three conditions should be performed in the same session.

-----------------------------
Keep all of the following unchanged across A1, B, and A2:

- same Raspberry Pi,
- same MPU6050,
- same helmet,
- same physical sensor mounting,
- same helmet position,
- same room/location,
- same table/surface,
- same orientation,
- same trained model,
- same INT8 TFLite model,
- same classifier threshold,
- same reconstruction threshold,
- same 3-window confirmation policy,
- same EMA preprocessing,
- same CPU governor,
- same CPU frequency,
- same TFLite thread count,
- same background services,
- same desktop/IDE state,
- same scheduler policy,
- same CPU affinity,

Do NOT intentionally move the helmet between the three runs.

Do NOT retune thresholds.

Do NOT restart the Pi between A1, B, and A2 unless technically unavoidable.

If a restart is unavoidable, record it explicitly.


CONDITION A1 — DEPLOYED POLLING BASELINE
----------------------------------------
Run the current deployed acquisition path exactly as used in the normal HelmX crash-monitor configuration.

Acquisition mode:
- current deployed polling / sleep-paced userspace I2C path.

Duration:
- 20 minutes.

Save all raw results.


CONDITION B — FIFO / DECIMATED ACQUISITION
------------------------------------------
Run the previously implemented FIFO/decimated acquisition path.

Important:
- change only the acquisition mechanism,
- keep the model and decision logic identical,
- do not alter thresholds,
- do not alter preprocessing intentionally,
- do not alter physical conditions.

Duration:
- 20 minutes.

Save all raw results.


CONDITION A2 — DEPLOYED POLLING REPEAT
--------------------------------------
Immediately return to the exact same deployed polling configuration used in A1.

Duration:
- 20 minutes.

This third run is essential.

Its purpose is to determine whether any difference seen in B follows the acquisition mode rather than time drift, environmental change, or gradual sensor/temperature change.

PRIMARY RESEARCH QUESTION
-------------------------
The purpose is to answer:

"With physical conditions, model, thresholds, preprocessing, system load and runtime configuration held as constant as practicable, does switching from the deployed polling acquisition path to the FIFO/decimated path systematically alter the reconstruction-error distribution or confirmed-trigger behavior?"


INTERPRETATION RULES
--------------------
Scenario 1:
A1 = no reconstruction triggers
B  = reconstruction triggers
A2 = no reconstruction triggers

Interpretation:
Strong evidence that the acquisition-path change is associated with the altered reconstruction behavior under this matched test.

Do NOT automatically claim the precise mechanism.


Scenario 2:
A1, B and A2 all behave similarly.

Interpretation:
The earlier FIFO-trigger observation was likely run-specific/environment-specific rather than a stable acquisition-mode effect.


Scenario 3:
A1 differs from A2 substantially.

Interpretation:
The experimental conditions were not sufficiently stationary to isolate acquisition mode. Report the test as inconclusive.


Scenario 4:
B improves timing continuity but also shifts model scores.

Interpretation:
Report both effects separately.

Do not present FIFO as an unqualified improvement.


IMPORTANT CLAIM LIMITS
----------------------
Do NOT claim:

- FIFO is inherently unsafe,
- polling is inherently superior,
- FIFO causes reconstruction errors by a specific internal mechanism unless proven,
- the result generalizes to all MPU6050 systems,
- the stationary test establishes real-road false-positive behavior,
- the stationary test establishes crash-detection reliability.


STOPPING RULE
-------------
After this A1 -> B -> A2 experiment:

STOP Raspberry Pi testing for the current IEEE Sensors Journal paper.

No additional Pi experiment should be added unless:

1. this experiment fails because of a technical/protocol problem and must be repeated, or
2. an actual journal reviewer explicitly requests additional evidence.

The remaining work should then move to:

- final data analysis,
- manuscript revision,
- supplement revision,
- figures/tables,
- reproducibility archive,
- submission preparation.
